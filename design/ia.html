What changed in v0.2

Decisions from review

Spend analyticsOwn tab. Analytics replaces the spend view inside Home. Home becomes the receipts inbox.
Who uses itOne person. No household members, no “added by”, no live list presence.
Server connectionFirst-class sync. New onboarding steps to find, pair and first-sync a server, a Server & sync area in Settings, and one sync status model used across the app.
Manual entryRemoved. Receipts only arrive as images. A failed receipt can be retaken or reprocessed.
Capture vs shareOne flow. Camera, Photos and the iOS share sheet all land on the same Add receipts screen (C.3).
Principles

Four rules the structure follows

One way in for receipts

Whether a receipt comes from the camera, Photos or another app's share sheet, it lands on the same screen with the same Send button. People learn it once.

Review is a queue, not a form

Unmatched lines are shown one at a time with the best guess first. Each confirmation teaches an alias, so the queue shrinks with use.

Every price is per unit

Anywhere a price appears next to another shop's price, it is shown per kg, L or piece. Shelf price and paid price are both kept.

The server is home, the phone is a copy

The phone keeps a working copy of products, shops and the list, and queues uploads. Sync status is always one glance away and never blocks the list in a shop.

Navigation model

Four tabs, one Add button, three global surfaces

A floating pill tab bar (Alan) with a detached Add button (MoonPay's pinned primary actions). Home is the receipts inbox; Analytics holds every chart and total.

Server & sync

Connecting to the home server, and staying in step

The app is useless until it has paired with a server, so pairing is the onboarding. After that, sync runs in the background and only surfaces when something needs attention.

Setting up (onboarding)

Find the server: Pantry servers on this Wi-Fi are listed automaticallyO.2
Or scan the QR code on the server's setup page, or type its addressO.2
Pair: a 6-digit code appears on the phone; approve it on the serverO.3
First sync: shops, categories, products, list and recent receipts downloadO.4
Away from home: add the Tailscale address so sync keeps workingO.4 · S.1

Syncing · 3 uploadsPill shows while uploads or the first sync are in progress.
Offline · 2 waitingNo network. Everything still works; receipts wait in the upload queue.
Server unreachableNetwork is fine but the server doesn't answer. Pill links to Server health.
Pairing expiredToken rejected. Full-screen prompt to pair again; local data is kept.

Receipt lifecycle

One status, shown the same way everywhere

Receipt status drives the Home attention card, the Home filter, the tab badge and push notifications. Each state has one colour and one label across the app.

pending

Stored on the phone, waiting for the server. Shown as “Waiting to upload”.

processing

OCR and structuring running, 30–120 s. Progress row with shop guess when known.

needs_review

Total mismatch or unmatched lines. Badge on Home tab, card at the top of Home.

ok

Totals match, all lines linked. Counts toward Analytics. No badge.

failed

Unreadable or job error. Offers Reprocess or Retake.

Open decisions

Smaller calls I'll make unless you say otherwise

How does the phone find the server?

Options: automatic discovery on the home Wi-Fi, a QR code on the server's setup page, or typing an address.

Proposed: all three on one screen, discovery first. QR covers Tailscale-only setups.

How is pairing approved?

The server needs to trust the phone before issuing a token.

Proposed: phone shows a 6-digit code; approve it on the server's web page or CLI (pantry pair approve).

Where does Unpack live?

It scans products, not receipts, but it is still “adding something”.

Proposed: in the Add sheet as the third option, and as a scan button on Products.

Does Home show any spend number?

Analytics now owns totals. A small figure on Home would duplicate it.

Proposed: no. Home is purely the receipts inbox; Analytics is one tap away.
