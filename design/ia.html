What changed in v0.4

Password sign-in and a design system

Auth (v0.4)URL + password. The app posts the password to POST /v1/auth/pair, the server returns a bearer token, and the app keeps only the token in the Keychain. The password is never stored. Replaces “run shop token create and paste” in the app; the CLI token command stays for assistant/MCP clients.
Onboarding (v0.4)Welcome, Server, Password, Ready. Settings › Server & sync gains Change URL, Change password and Sign out. “Token rejected” becomes “Session expired”.
Shop marks (v0.4)22 px logo marks from logo.dev, cached per shop, with a monogram fallback. Needs a publishable key as build config.
Design system (v0.4)Tabular numbers, bold only for headers, motion and haptics specified. Screens are interactive prototypes and exist in dark mode. See Design system below.
Earlier (v0.3)The rows below are the v0.3 decisions, kept for reference.
Finding the serverTyped URL. One field, then Test connection. Works the same for LAN and Tailscale addresses.
Pairing (replaced in v0.4)Was: via the server. Create a token on the Mac mini (shop token create iphone) and paste it into the app. Stored in the Keychain.
HomeShows spending this month above the receipts inbox. Tapping it opens Analytics.
PhasesRemoved. Every screen here ships. M9 items in the plan (widgets, bank import, label OCR) stay out until you opt in.
Input (plan §0)Paper receipts only, via the document scanner. Screenshot import and the share sheet are gone, so Add has one receipt path: Scan → pick shop → queued.
Shop (plan §0)You pick the shop for each receipt, with the last one preselected. No automatic shop detection, so the Pick shop fallback is gone.
Review (plan §9)One review screen, not a queue. Image on top, lines below, a sticky Σ vs total bar, and Confirm always enabled. Link product shows 3 fuzzy suggestions, search, and New product.
No push (plan §9)Processing updates by polling. Home refreshes while receipts are processing; no notification settings.
Manage (plan §9)Shops and categories are edited in Settings. Backup health from the NAS shows there too.
Principles

Four rules the structure follows

Scan soon, review later

Thermal paper fades. Scanning takes two decisions (keep the scan, confirm the shop) and then gets out of the way. Review happens whenever you have a minute.

The receipt is the review

A receipt that needs attention opens straight into review mode: image, lines, and the running sum against the printed total. Confirm is always available, because some receipts are just odd.

Every price is per unit

Anywhere prices from different shops sit together, they are shown per kg, l or piece after linked discounts, formatted the Dutch way (€ 1,29).

The server is home, the phone is a copy

Products, shops and the list are cached on the phone and uploads queue offline. Sync status stays out of sight until something needs you.

Navigation model

Four tabs, one Add button, three global surfaces

A floating pill tab bar (Alan) with a detached Add button (MoonPay's pinned primary action). Home is this month plus the receipts inbox; Analytics holds every chart.

Design system

Rules every screen follows

Summary only. Source of truth: DESIGN-RULES.md. Motion detail: motion.html and MOTION.md.

TypeGT America + GT America Mono. Numbers are tabular everywhere. Bold (700) only for screen and tray headers and the hero number; rows, labels, buttons and chips use 400 or 500. Receipt text and barcodes in Mono.
ColourTokenised light and dark. Accents are shared across themes; amber always means “needs review”. Categories have fixed colours. Tray tint carries meaning (destructive trays are red).
Shop marks22 px in lists, 28 px in headers, max 32 px. logo.dev logo cached per shop, monogram fallback in the brand colour. The logo.dev publishable key is a build-time config value still to be supplied.
DensityFlat 44–52 px rows, hairline dividers, no card backgrounds for lists, grouped by day with a day total. Aim for 9–12 rows per screen.
TraysSoft tactile trays over a scrim. Tray-to-tray changes animate height while content cross-fades.
MotionSpring for trays and toggles, ease for fades and slides, 0.97 press scale, digit roll on totals, staggered first paint. Reduced motion keeps 120 ms fades. See motion.html and MOTION.md.
Hapticsselection, light, medium, soft, plus success, warning and error notifications mapped to specific actions (for example error on wrong password, success when pairing succeeds). See DESIGN-RULES.md.
PrototypesScreens are interactive prototypes (real links, inputs and state) and each also exists in dark mode.
Server & sync

Connecting to the Mac mini, and staying in step

The app does nothing until it can reach the server, so connecting is the onboarding. After that, sync runs in the background and only surfaces when something needs attention.

Setting up

Receipt lifecycle

One status, shown the same way everywhere

Status drives the Home attention card, the Home filter and the tab badge. Each state has one colour and one label across the app.

pending

On the phone, waiting to upload. Shown as “Waiting to upload”.

processing

OCR and parsing on the server, about 4–15 s. Row shows shop and a spinner.

needs_review

One or more reasons: no total, total mismatch, line math, no date, low confidence, unparsed rows.

ok

No reasons, or you confirmed it. Counts toward Analytics and prices.

failed

Image couldn't be read. Offers Re-run OCR or Delete and rescan.

MoonPay→ H, A, H.1, S

  • Monochrome base, pill buttons pinned to the bottom
  • Inset grouped settings rows with icon tiles
  • Detail card with label / value rows
Alan→ tab bar, H, L
  • Floating pill tab bar with a detached action
  • Soft cards with a trailing arrow for “do this next”
  • Friendly empty states with one clear action
Base→ H, P
  • Plain, dense activity lists
  • Restrained use of one accent colour
Fuse→ A, O, P.1
  • Large numerals with quiet secondary text
  • Bottom sheets for focused tasks
  • Calm, step-by-step setup screens
